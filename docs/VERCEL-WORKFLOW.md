# InstaEdit — Correct workflow for changes, push and Vercel deploy

This guide describes the standard flow for editing InstaEdit and making sure
Vercel publishes UI updates correctly. Keep all copy, docs and commit messages
in English.

## URLs

- Public landing: `https://app.instaedit.org`
- `https://instaedit.org` and `https://www.instaedit.org`: redirect to the
  canonical landing.
- Public API: `https://api.instaedit.org`

Never use the server IP address in application links or Vercel variables. The
IP is only useful for local host diagnostics.

## Project structure

- `web/src/`: UI pages, components and logic.
- `web/public/`: static assets.
- `web/vercel.json`: Vercel config, SPA rewrite and domain redirects.
- `internal/`, `pkg/`, `cmd/`: Go backend.
- `docs/`: documentation.

For a frontend change work normally in `web/src/`. Do not edit `web/dist/`
manually: it is regenerated by the Vite build.

## Vercel variables

If the landing must call the API, the frontend variable must use the public
API domain:

```text
VITE_API_BASE_URL=https://api.instaedit.org
```

Set it at least for the `Production` environment. Do not use:

- `http://localhost:8080` in Production;
- a `*.vercel.app` URL as the API;
- the server IP address.

`VITE_*` variables are baked in during the build. After changing one of them
a new deploy or redeploy is mandatory.

## Important: which Vercel project owns the public domain

There are **two** Vercel projects linked in this repo — they are different:

| Link location | Project | Serves | Root directory |
|---------------|---------|--------|----------------|
| repo root (`.vercel`) | `instaedit-login-267l` | `app.instaedit.org`, `instaedit.org`, `www.instaedit.org` | `web` |
| `web/.vercel` | `instaedit-login` | `instaedit-login.vercel.app` (NOT the public domain) | — |

**Deploy the UI from the repo root** so the deploy targets
`instaedit-login-267l` (the project that owns `app.instaedit.org`). Deploying
from `web/` targets the other project and the public domain keeps serving the
old bundle.

## Before committing

From the repository root:

```bash
git status --short
git diff --check
```

For frontend changes:

```bash
cd web
npm ci
npm run check:env
npm test
npm run build
cd ..
```

For backend changes:

```bash
go test ./...
go vet ./...
```

Then make sure no secrets or local files are present:

```bash
git status --short
git diff --stat
```

Never commit `.env*` files, Vercel tokens, Google client secrets, refresh
tokens, OAuth JSON files or generated system files. `.env*` is gitignored;
the `.example` files only ever contain empty placeholders.

## Commit and push

Use small, descriptive commits:

```bash
git add web/src/path/to/file.tsx docs/path/to/doc.md
git diff --cached --check
git commit -m "fix(web): short description of the change"
git push origin main
```

Before pushing verify the commit being published:

```bash
git log -1 --oneline
git status --short
```

The working tree should be clean after the push. Do not use `git add .` when
the directory contains local files or secrets not intended for the repository
(keep `docker-compose.yml.bak` untracked).

## How Vercel publishes updates

The Vercel project must have:

- Root Directory: `web`;
- Framework Preset: `Vite`;
- Install Command: `npm ci`;
- Build Command: `npm run build`;
- Output Directory: `dist`;
- Production Branch: `main`.

With the GitHub connection active on the correct project
(`instaedit-login-267l`), a push to `main` automatically creates a new Vercel
deployment. Check it in Vercel → **Deployments**: the deployment must reference
the commit just pushed and be in **Ready** state.

If the auto-deploy does not start, use the CLI from the **repo root**
(explicitly NOT from `web/`):

```bash
vercel --prod
```

The CLI is already authenticated for every agent: the token is stored in
`~/.vercel/auth.json` (mode 600) and exported as `VERCEL_TOKEN` in
`~/.bashrc` / `~/.profile`. Never write the token into commits or project
files.

## Verifying after the deploy

Check that the deployed bundle is the new one (cache `age` should reset to a
small value and the JS/CSS hashes change):

```bash
curl -s https://app.instaedit.org/ | grep -oE 'assets/index-[A-Za-z0-9_-]+\.(js|css)'
curl -sI https://app.instaedit.org/ | grep -iE '^age|x-vercel-cache'
curl -fsS https://api.instaedit.org/api/v1/health
```

Then open `https://app.instaedit.org` with a hard refresh and check the
landing sections (hero, founder story, testimonials, FAQ, final CTA).

If the UI still shows an old version:

1. verify Vercel published the correct commit;
2. check `VITE_API_BASE_URL` is set in the correct environment;
3. do a redeploy after any `VITE_*` change;
4. hard-refresh the browser (the CDN cache can take a moment to invalidate).

## Backend is separate

Pushing the landing UI to Vercel does not update the Go backend. After
changes to `internal/`, `pkg/` or `cmd/`, follow the backend runbook and
verify migrations before rollout.
